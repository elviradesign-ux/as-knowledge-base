# Style Guide — правила написания статей

> Как писать статьи базы знаний. Опирается на принципы [MANIFESTO](MANIFESTO.md).
> Структуру статьи задаёт [ARTICLE_TEMPLATE](ARTICLE_TEMPLATE.md).

## Тон и голос

- **От второго лица, дружелюбно и по делу.** «Нажмите», «Откройте»,
  а не «Пользователь должен нажать».
- **Активный залог.** «Система создаёт заказ» вместо «Заказ создаётся системой».
- **Настоящее время.** «Кнопка открывает модалку», а не «откроет».
- Без жаргона и без канцелярита. Термины — только из [GLOSSARY](GLOSSARY.md).

## Структура текста

- Начинай с результата: что читатель получит, выполнив статью.
- Один абзац — одна мысль. 2–4 предложения.
- Шаги — нумерованным списком, по одному действию на шаг.
- Перечни без порядка — маркированным списком.
- Заголовки описывают задачу («Создание заказа»), а не систему («Модуль заказов»).

## Форматирование

| Элемент | Правило |
|---------|---------|
| Названия кнопок/полей | **жирным**: нажмите **Save** |
| Пути в UI | Меню → Подменю → Пункт |
| Код, значения, ID | `моноширинным` |
| Термины глоссария | ссылка при первом упоминании → [GLOSSARY](GLOSSARY.md) |
| Экраны | ссылка на статью экрана из [SCREEN_CATALOG](SCREEN_CATALOG.md) |
| Предупреждения | блок `> ⚠️` |

## Скриншоты

- Показывают то, о чём текст, — не декорация.
- Единый масштаб и хром браузера/окна.
- Аннотации (стрелки, рамки) — фирменным акцентом, единым по всей базе.
- Не содержат реальных персональных данных клиентов — только тестовые.
- Имя файла: `screen-name--action.png`.

## Терминология платформы (обязательно)

- Названия ролей — как в [PERMISSIONS_MATRIX](PERMISSIONS_MATRIX.md): Client,
  Buyer, Supervisor, Researcher, Storekeeper, Freelancer, Admin. Помни:
  **Freelancer** в коде/роутах = **Service Provider**.
- Статусы заказа пишем точно по [GLOSSARY](GLOSSARY.md) (Pending, Ready to buy,
  At process, Ready for payment, …) — не выдумываем формулировки.
- Сущности называем единообразно: карточка продукта, заказ, коробка, партия,
  идея, поставщик — определения в [GLOSSARY](GLOSSARY.md).
- Экраны обозначаем по route + `SCR-###`; модалки — по имени компонента
  (`CreateOrderModal`) + `SCR-M###`.

## Ссылки и переиспользование

- Не дублируй контент — ссылайся. Правило «один факт — одно место».
- Каждый workflow ссылается на экраны и термины, а не пересказывает их.
- Внутренние ссылки — относительными путями.

## Числа, даты, единицы

- Даты в тексте — абсолютные и в формате `YYYY-MM-DD`.
- Единицы измерения и валюты — согласно [LOCALIZATION_GUIDE](LOCALIZATION_GUIDE.md).

## Доступность

- Каждому изображению — осмысленный `alt`.
- Не «нажмите сюда»: текст ссылки описывает цель.
- Не полагайся только на цвет для передачи смысла.

## Чек-лист перед публикацией

- [ ] Есть шапка из [ARTICLE_TEMPLATE](ARTICLE_TEMPLATE.md) (владелец, дата, роли).
- [ ] Термины связаны с [GLOSSARY](GLOSSARY.md).
- [ ] Экраны связаны с [SCREEN_CATALOG](SCREEN_CATALOG.md).
- [ ] Проверена актуальность на текущей версии продукта.
- [ ] Скриншоты без реальных ПДн.
- [ ] Текст пригоден к переводу (см. [LOCALIZATION_GUIDE](LOCALIZATION_GUIDE.md)).
