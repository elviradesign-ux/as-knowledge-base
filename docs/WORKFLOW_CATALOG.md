## Как читать таблицу

| Поле | Значение |
|------|----------|
| ID | Стабильный `WF-###`, на него ссылаются статьи |
| Сценарий | Что делает пользователь |

> Статусы, которыми управляют эти сценарии (товар, заказ, идея, коробка,
> партия), — в [ENTITY_STATES](ENTITY_STATES.md).

## Сквозной процесс платформы (E2E)

Товар проходит через роли по цепочке (из Role Map). Это «главный» сценарий, из
которого вырастают частные. Каждый шаг меняет статус товара/заказа — коды в
[ENTITY_STATES](ENTITY_STATES.md):

```
WF-001 Researcher создаёт карточку товара
WF-002 Supervisor проверяет и утверждает карточку, верифицирует поставщика
WF-003 Buyer ищет поставщика, заполняет данные, возвращает Supervisor
WF-004 Supervisor публикует карточку на биржу товаров
WF-005 Client покупает карточку с биржи и создаёт заказ
WF-006 Buyer обрабатывает заказ (жизненный цикл статусов)
WF-007 Storekeeper принимает коробки, распределяет, формирует партию
WF-008 Buyer получает уведомление «Ожидает подтверждения заказа»
```

## Правила ведения

- Один сценарий — одна цель пользователя. Две цели → раздели.
- ID не переиспользуется после удаления.
- Каждый сценарий ссылается минимум на один экран из [SCREEN_CATALOG](SCREEN_CATALOG.md).
- Термины — из [GLOSSARY](GLOSSARY.md).
- Новые сценарии добавляются в конец блока роли, ID монотонно растёт.
