# Localization Guide — правила перевода

> Как переводить базу знаний на EN / RU / UA / ZH. Термины берутся из
> [GLOSSARY](GLOSSARY.md); стиль — из [STYLE_GUIDE](STYLE_GUIDE.md).

## Языки и приоритет

Платформа Seller Exchange поддерживает 4 языка через переключатель в хедере
(порядок в продукте: **EN / RU / ZH / UA**, см.
`wiki/ФУНКЦИОНАЛ/Localization.md`).

| Код | Язык | Роль в продукте / КБ |
|-----|------|------|
| `en` | English | Основной язык международных клиентов |
| `ru` | Русский | Язык-источник документации (пишем на нём) |
| `zh` | 中文 (упрощённый) | Азиатский рынок (поставщики, склады) |
| `ua` | Українська | Локальный рынок |

Источник истины документации — `ru`. Остальные — переводы; при расхождении
правим источник, затем переводы. В самом продукте строки переводятся через
Admin → Настройки → **Динамические переводы** (`DynamicTranslationsView`) —
термины UI берём оттуда, не переводим на слух.

## Процесс

1. Статья пишется и утверждается на `ru` (`status: published`).
2. Переводы создаются из финальной версии, не из черновика.
3. Поле `locales` в шапке ([ARTICLE_TEMPLATE](ARTICLE_TEMPLATE.md))
   перечисляет готовые языки.
4. При обновлении источника все переводы получают `status: review`.

## Файлы локализации продукта (источник точных формулировок)

Строки интерфейса живут в `figma-mcp/localizations/` — по файлу на язык
(`en.tokens.json`, `ru.tokens.json`, `uk.tokens.json`, `zh.tokens.json`,
формат W3C design-tokens: `{ "$value": "…" }`). ~2450 ключей на язык. Это
**канонический источник UI-строк** — из него берём точные названия кнопок,
подписей и сообщений при написании статей, а не переводим на слух.

Структура ключей по префиксам:

| Префикс | Кол-во | Что это | Как использовать в документации |
|---|---|---|---|
| `actions_*` | ~115 | Действия/кнопки (глаголы-процессы) | Названия шагов и кнопок в **Workflow**-статьях |
| `info_*` | ~2270 | Подсказки, подтверждения, тексты модалок | Дословные предупреждения (`> ⚠️`), пояснения |
| `label_*` | ~18 | Метки полей | Названия полей в статьях экранов |
| `error*`, `confirm*`, `title*` | единично | Ошибки, подтверждения, заголовки | Разделы «Частые проблемы», диалоги |

### Процессы из `actions_*` → сценарии

Ключи `actions_*` — это фактический перечень действий пользователя и хорошая
основа для именования шагов и сверки [WORKFLOW_CATALOG](WORKFLOW_CATALOG.md).
Примеры (key → EN / RU): `createOrder` → Create order / Создать заказ,
`addBox` → Add a box / Добавить коробку, `addToBatch` → Add to batch /
Добавить в партию, `acceptDeal` → Accept the deal / Принять сделку,
`cancelOrder` → Cancel order / Отменить заказ, `savePreset` → Save preset /
Сохранить пресет, `addToInventory` → Add to inventory / Добавить в инвентарь.

> Правило: описывая шаг, называй кнопку ровно так, как в `actions_*` для нужного
> языка (**Save**, **Add a box**), не перефразируя.

## Терминология

- Переводы терминов берём **только** из [GLOSSARY](GLOSSARY.md) — не
  придумываем на месте.
- Если термина нет в глоссарии, но есть в `*.tokens.json` — сначала заносим в
  глоссарий из локализации, потом используем.
- Названия элементов интерфейса переводим согласно локализации самого
  продукта, а не дословно.
- Термины без утверждённого перевода помечаем `(TODO: <lang>)`.

## Что НЕ переводим

- Идентификаторы: `WF-001`, `SCR-001`, `VariableID`, имена файлов.
- Код, значения токенов, API-поля.
- Названия брендов и продуктов.

## Язык и форматы

| Аспект | ru | en | ua | zh |
|--------|----|----|----|----|
| Даты | `ГГГГ-ММ-ДД` | `YYYY-MM-DD` | `РРРР-ММ-ДД` | `YYYY-MM-DD` |
| Десятичный разделитель | запятая | точка | запятая | точка |
| Валюта | по данным продукта | по данным продукта | по данным продукта | по данным продукта |
| Кавычки | «ёлочки» | "double" | «ялинки» | 「」 |

## Пригодность текста к переводу (пишущему на `ru`)

- Не встраивай слова в изображения — используй подписи/alt.
- Избегай идиом и каламбуров — они не переводятся.
- Не склеивай строки конкатенацией переменных — переводчик потеряет контекст.
- Одно предложение — одна мысль (упрощает перевод и вычитку).

## Хранение переводов

- Файлы: `<article>.<lang>.md` (например, `create-order.en.md`).
- Шапка перевода дублирует `related_*` и `owner` из источника.
- Ссылки внутри перевода ведут на переводы того же языка, если они есть,
  иначе — на источник.
